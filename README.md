# tinderbox

A full-screen WebGL2 [Drossel–Schwabl forest-fire model](https://en.wikipedia.org/wiki/Forest-fire_model).

Each step, every cell updates at the same time:

- **Burning → empty**
- **Tree → burning** if any neighbor is burning, or with probability **f** (lightning)
- **Empty → tree** with probability **p** (growth)

The interesting regime is f ≪ p ≪ 1. Fires then follow a power-law size distribution (self-organized criticality).

## Run

```sh
npm install
npm run dev
```

**Controls:** use the panel to set cell size, p, f, speed, seed density, neighborhood, and edge wrap. Keys:

- `H` or the × / ☰ buttons hide and show the panel
- `F` toggles fullscreen
- `Space` pauses
- `.` steps once

Click or drag on the canvas to start fires. Settings, including whether the panel is hidden, are saved in localStorage.

## Layout

- `src/shaders.ts`: GLSL for the update rule and the flat and sprite renderers, plus the state, cause, and clip encoding
- `src/atlas.ts`: loading the sprite atlas, and the procedural placeholder used when there isn't one
- `src/sim.ts`: ping-pong framebuffer simulation, resizing, and ignition
- `src/controls.ts`, `src/params.ts`: the parameter panel and its saved settings
- `src/main.ts`: the frame loop, input handling, and fullscreen

## State encoding

One `RGBA8UI` texel per cell holds:

- `R`: the current state (`EMPTY`, `TREE`, `FIRE`)
- `G`: the previous state
- `B`: the cause of the last transition (`GROW`, `SPREAD`, `LIGHTNING`, `BURNOUT`)
- `A`: for `SPREAD`, a bitmask of the neighbors that were burning

This gives the renderer the full temporal transition for each cell without extra passes.

## Sprites

> This per-cell atlas is the v0 approach and has visible seams. It is being replaced by dual-grid tiles; see [docs/PLAN.md](docs/PLAN.md).

With **Sprites** on, each cell plays a clip from a texture-array atlas. There are seven clips:

- `empty` and `tree` loop on wall-clock time, with a per-cell phase offset.
- `grow`, `spread-edge`, `spread-corner`, `lightning`, and `burnout` play once over the step that caused them.

The spread clips are drawn with fire arriving from the west (edge) or the south-west (corner). The renderer rotates them toward an actual burning neighbor taken from `A`. Transitions are only readable at low speeds (a few steps/s) and large cells.

If `atlas/atlas.{png,json}` exists in the data dir (`$TINDERBOX_DATA`, default `~/.local/share/tinderbox`) it's used; `vite.config.ts` serves it in dev and copies it into `dist/` on build. Otherwise a procedural placeholder is drawn at startup. To generate the real atlas with Wan2.1-VACE-1.3B (about 10 GB of VRAM; it takes a turnstile GPU lease when one is available):

```sh
cd tools/atlas
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python generate.py              # keyframes → clips → pack
# On bifrost, IPv6 to Hugging Face times out: download weights once over IPv4
# (see docs/PLAN.md), then run with HF_HUB_OFFLINE=1.
.venv/bin/python generate.py --only tree  # redo one clip, then repack
```

Every clip is interpolated between three shared keyframes (`$TINDERBOX_DATA/work/keyframes/{empty,tree,fire}.png`), so each transition ends on the exact frame the next clip starts from. To change the art direction, swap in your own keyframes and rerun `clips`.

## Roadmap

- **Phase 1 (done):** GPU sim, flat-color renderer, adjustable parameters, fullscreen.
- **Phase 2 (in progress):** Per-cell animations generated by a video diffusion model, one clip per transition, packed into a sprite atlas (see [Sprites](#sprites)).
- Also planned: fire-size histogram and density plots (needs GPU reduction or async readback), and painting trees and firebreaks.
